# XOD — канонический формат сообщений агентам и пользователю

**Версия 1.0 · 2026-11-21 · утверждённое предпочтение 👤 ДИМЫ.**
**Область:** все чаты и агенты, занятые разработкой XOD, когда они ознакомились с этим документом. **Канонический источник:** этот файл в рабочей ветке GitHub `ai-workspace`, а не копии инструкций в старых переписках.

## 1. Идентификаторы и статусы

- 🟩 **SOL** — Work-интегратор и фактический владелец локальной сборки XOD.
- 🟦 **CHAT** — обычный чат, готовит автономные компоненты/патчи/тесты.
- 🟪 **ASTRA** — эксперт при архитектурной эскалации.
- 👤 **ДИМА** — пользователь.
- **Текущий шаг** упоминать явно в каждом содержательном ответе.
- Никакого предположения, что другой агент «проснулся», закончил работу, получил сообщение или увидел обновление, без подтверждения. В период ограничений SOL спит до прямого сообщения 👤 ДИМЫ. Данные лимитов приводить только как *последние сообщённые*, не как текущий остаток.
- 🟦 CHAT вправе самостоятельно выполнять автономные задачи во время паузы SOL. Не требовать ручной пересылки: писать готовые файлы и краткий журнал в GitHub.

## 2. Единая нумерация — от стратегии к тактике

Путь минимум из четырёх уровней, например:
`1. XOD 3.0 → 1.1. YouTube → 1.1.1. Виды таблицы → 1.1.1.1. Текущий шаг · 🟦 CHAT — группировка`.

После завершения шага указывать, какой **следующий** шаг и кому он назначен. Новые самостоятельные этапы получают собственные ID. Внутри шага можно перечислять подэтапы `1.1.1.1.1`, `1.1.1.1.2`, etc. Не смешивать этапы плана с хронологией событий.

## 3. Промежуточные сообщения

Форма: одна ясно маркированная цитата Markdown:
> **◌ ПРОМЕЖУТОЧНО · 🟦 CHAT · 1.1.1.1**
>
> Что проверено / обнаружено / что делается. Без итоговых формулировок.

Не выдавать промежуточные статусы за финальные, не писать «передано SOL» до фактической передачи через общий журнал. Промежуточные сообщения в одном активном сеансе полезны, но не означают работу в фоне между запросами.

## 4. Финальное сообщение

**Весь финальный отчёт — в одной визуальной рамке** (в поддерживающем разметку ChatGPT — компонент box с border+radius+padding; в иных клиентах — текстовый разделитель).

Внутри — **отдельные цитаты** Markdown, **хронологически упорядоченные** от начатого к завершённому, не обязательно все операции:
> **1.1.1.1.1 · 🟦 CHAT · Сделано**
>
> [Короткий результат + ссылка на канонический файл]

> **1.1.1.1.2 · 🟦 CHAT · Проверено**
>
> [Какие тесты действительно запускались, PASS/FAIL/не проводились]

> **1.1.1.1.3 · 🟦 CHAT · Записано для SOL**
>
> [Ссылка на живой handoff-документ и точное состояние]

После цитат — заметная строка **«Текущий шаг»**, метка **«👤 ДИМА»** с одним конкретным действием или «никаких действий», а также минимальные существенные риски. **Переход к SOL только по факту завершения паузы, сообщённому 👤 ДИМОЙ**; до этого текущий исполнитель — CHAT.

Ориентир на компактность: обычно 2–4 цитаты, а не длинный журнал; подробности в GitHub. Не повторять неизменившиеся сообщения.

## 5. Общая память, ограничения и обязанности

- После каждого **существенного** шага обновлять `ai-workspace/handoffs/work-resume-latest.md`, записывая хронологию, результат, ссылки, тесты, открытые риски и рекомендуемое продолжение.
- Готовый код и тесты размещать в `ai-workspace/submissions/chat-NN/`; версионное редактирование вместо параллельных копий для одного артефакта.
- `main` не изменять; изменения в SOL-сборке без прямой проверки не утверждать.
- Разные чаты **не читают GitHub автоматически**: каждый агент должен получить этот канонический путь через свою проектную инструкцию/контекст или явную ссылку. GitHub — единая версия правил, но не автоматическая глобальная настройка ChatGPT.
- После паузы SOL начинает с канонического журнала и этой инструкции; CHAT не прекращает инициативную работу лишь потому, что готов один пакет.

## 6. Мини-образец рамочного финала

В клиенте, поддерживающем DIL/богатую разметку, поместить в `<box border radius="lg" padding={3}>` (закрыть `</box>`) заголовок и **три Markdown-цитаты**. Все цитаты расположить хронологически. Не вставлять синтаксис DIL в файлы кодовой базы XOD.

Последний ввод 👤 ДИМЫ имеет приоритет над данным протоколом и может изменить его версию.
