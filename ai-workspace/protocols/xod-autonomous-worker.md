## 1. Общие гарантии каждого цикла
1. Прочти актуальный журнал. Если SOL_STATE != SLEEPING — не разрабатывай, **поставь на паузу свою запланированную задачу**, если доступен Automations update, и явно сообщи об ограничениях, иначе остановись.
2. Прочти lock и его blob SHA. Если `state=running` и срок `expires_at` в будущем — не начинать параллельную работу. Если idle/истекло — захвати через GitHub update_file с текущим `sha` (оптимистическая блокировка). При конфликте SHA остановись. Выбирай уникальный owner на каждый запуск.
3. Lock lease до 70 минут, но после завершения обязательно освободи. Если работа длится дольше 15 минут — обновляй heartbeat и продлевай expires_at по актуальному sha. Перепроверяй блокировку и SOL_STATE перед каждым существенным коммитом. Не изменяй чужие данные и не форсируй SHA.
4. Работай максимально содержательно: тесты, воспроизводимые дефекты, высокоценный автономный патч, модуль, непрерывные проверки, но избегай фантазий об актуальной локальной сборке SOL. Используй оригиналы в GitHub; сохраняй неинтегрированные исправления SOL. У задачи должен быть наблюдаемый результат, а не «видимость деятельности».
5. После каждого существенного результата **обновляй существующий журнал** с выполненным, проверенным, непроверенным, ссылками, рисками и следующим действием. Оставь checkpoint, чтобы следующий запуск не повторял работу. Если остаётся полезная самостоятельная работа — продолжай в текущей итерации, а не останавливайся ради расписания.
6. Заверши с коротким отчётом по каноническому формату, освободив lock, если owner совпадает. Ошибки/недоступность инструментов не скрывать; результаты тестов заявлять только при фактическом исполнении.

### 2.1. Одноразовая инициализация в чате XOD

👤 ДИМА отправляет в рабочий XOD-чат одну подготовленную команду (см. 2.3). После этого 🟦 CHAT в каждом финальном ответе этого чата добавляет работающую кнопку **«Продолжить XOD · GPT-6 High»**, вызывающую host action `GenUI.issueNewTurn` **из прямого клика пользователя**, с краткой командой «продолжи по каноническому протоколу и GitHub checkpoint». Кнопка в чате настройки автоматизаций не должна незаметно запускать код XOD.

### 2.2. Загрузка и выполнение одного запуска

1. Прочитать канонический GitHub-журнал и его **текущий** `SOL_STATE`. Не делать вывод о пробуждении SOL по времени. Если состояние не `SLEEPING`, **не продолжать автономную разработку**.
2. Проверить действующий lock, захватить его через обновление с текущим SHA. Если lock занят — не ждать, не форсировать и не работать параллельно. В момент каждого существенного GitHub-коммита перепроверять lock и SOL_STATE.
3. Выбрать следующий **реально полезный** блок по состоянию исходников/реестру незавершённого, не создавать новую параллельную дорожную карту и не дублировать выполненную работу. Один вызов GPT-6 High должен охватывать **несколько логически связанных этапов**, где это безопасно: воспроизведение → исправление → тесты → commit → checkpoint → следующий автономный шаг. Не останавливаться после первого мелкого результата, если доступны следующие независимые шаги.
4. После каждого существенного блока обновлять журнал, фиксировать конкретные проверки, URL файлов и незавершённые риски. Перед завершением безопасно освободить lock, если он ещё принадлежит текущему сеансу.
5. В отчёте использовать канонические рамку и цитаты, **одну кнопку продолжения**. Не просить подтверждений на обратимые решения. Не утверждать, что модель работала в фоне или что пользователь не нужен, если возник настоящий блокер.

**Важно:** один клик запускает **один следующий ход в этом чате**, а не бессрочный фон. Автоматического повторного запуска GPT-6 High через Plus в подтверждённом доступном интерфейсе **нет**. Время хода нельзя гарантированно удлинить одним текстом промпта. Соотношение полезной работы и количества кликов оптимизируется размером задач, самопроверками и контрольными точками.

- Все запуски читают общее состояние из GitHub, а не предполагают общий контекст между отдельными чатами.
- Не включать Work/Codex и платный API. Scheduled CHAT может потреблять usage allowance Plus.

Программно через доступный Automations API модель не меняется.
- Пять почасовых Scheduled-задач сейчас **paused**. При их явном будущем включении они не гарантируют запуска точно по минутам; возможны задержки, блокировки, лимиты и остановки.
- После сигнала 👤 ДИМЫ о пробуждении 🟩 SOL остановить/поставить на паузу все XOD-задачи. При создании новых задач дописать их ID в журнал.
