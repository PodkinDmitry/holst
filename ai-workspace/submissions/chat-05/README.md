## 4. Как запустить SOL

1. **Не заменять исходный JS**: прежде интегрировать CHAT 04 как патч поверх актуального кода SOL (сохранить два уже сделанных исправления — запрет дублей сортировки и предел вложенности фильтра).
2. Для проверки отдельного исходного CHAT 04 расположить данный файл на уровне `ai-workspace/submissions/chat-05/` рядом с `chat-04/`; открыть `integration-gate.html`. Он загружает `../chat-04/xod-youtube-table300.js` и `.css`. Это работает при локальной файловой загрузке с разрешёнными локальными ресурсами либо через статический сервер.
3. Для проверки **реального интегрированного XOD** изменить ровно два `src`/`href` на фактический JS/CSS SOL, сохраняя тесты неизменными. Проверить все 8. Это и есть результат интеграционного gate.
4. Запустить `node randomized-group-audit.js ../chat-04/xod-youtube-table300.js` (или указать путь на действующий исходный JS SOL). Node.js требуется только для этого отдельного генеративного gate, не для компонента.
5. Занести PASS/FAIL и версии в `ai-workspace/handoffs/work-resume-latest.md` после явного восстановления SOL.

## 5. Риски и границы

- Fake-адаптеры подтверждают контракт взаимодействия компонента; **не** подтверждают реально устойчивую запись в XOD. SOL должен проверить существующий сериализатор вида: `group` не должен теряться при чтении/записи или изменении пресета, а явное `group:null` должно удалять группировку.
- Возможность применить повторную команду создания пресета после ответа-отказа может приводить к дубликатам на стороне сохранения, если запись состоялась, а ответ потерялся; дедупликация — зона SOL.
- Различие CHAT 04 и текущей версии SOL предполагается; пакет тестовый, без автоматической замены или изменения `main`.
- Формат сообщений для всех агентов закреплён в `ai-workspace/protocols/xod-response-format.md`; источник единой версии инструкций требует загрузки через проектный контекст каждого чата.
