# CHAT 18 — недопустимый переход между досками при отказе или незавершённой записи (22.11.2026)

**Статус:** воспроизведён реальный дефект логики исходной сборки Test 13, подготовлен минимальный **неинтегрированный** продуктовый патч и 15 воспроизводимых Node VM проверок. Работа в обычном CHAT, без Work. Исходный приватный код не публиковался.

## Источник и воспроизведение

- Приватный очищенный Test 13: ZIP `XOD-Test13-source-6429ad6.zip`, SHA-256 `a7f1f7e7ae1903ab524f19aea450d0329dbcde1bd6fb234ba8fc4be7d40cf9c4`, commit marker `6429ad61490301e4b942f2190b0be593d449309c`; 432 файла.
- В настоящем `v224/base29.html` прежние `openBoard()` и `createBoard()` вызывали `await saveNow()` при `dirty`, **не проверяя, завершилась ли запись успешно**. `saveNow()` перехватывает исключение, оставляет `dirty=true`, но не отклоняет промис; переключение продолжалось и прежняя доска вытеснялась. Отдельный опасный случай: если `saving=true`, `dirty=false`, сохранение уже в полёте, прежние переходы не ждут его.
- Ещё один исходный дефект: `Backend.saveBoard()` может вернуть `{removed:true}`, когда доска уже удалена; старый `saveNow()` при этом ставил статус `saved`. Проверено отрицательным тестом на реальной функции, а не предположено по интерфейсу.
- `duplicateBoard()` мог продолжать создание копии после отказа сохранения текущей доски; `deleteBoard()` вообще не ждал незавершённую текущую запись, рискуя гонкой с удалением.

## Минимальный патч

- [`board_navigation_guard.patch`](./board_navigation_guard.patch) — **Git blob `7e35ec332e401afbbfe950f08ca260a543a30e44`**, 3319 байт; меняет только `v224/base29.html`.
- В обычном `saveNow()` ответ `{removed:true}` теперь превращается в ошибку с `dirty=true` и статусом `error`; успешная запись по-прежнему вызывает `Backend.setLast()`.
- Добавлен `canLeaveCurrentBoard()`, который до перехода дожидается сохранения и окончания уже выполняющейся записи **до 5 секунд**, затем **запрещает переход**, если ещё есть `dirty/saving/saveAgain`, исходная доска сменилась или хранилище не ответило. Краткое предупреждение не раскрывает содержимое доски.
- `openBoard`, `createBoard`, `duplicateBoard` (для текущей доски), `deleteBoard` (для текущей доски) проверяют общий guard. Нормальные успешные операции сохранены. Для *dirty virtual board* через общий интерфейс переход запрещён, чтобы не доверять исходной fire-and-forget ветке; после принятия отдельного патча CHAT 17 использовать его подтверждённый путь сохранения.
- Это защита конкретных четырёх переходов, **не доказательство того, что все сценарии смены доски во всём приложении защищены**; другие прямые вызовы `loadBoard` требуют отдельной оценки.

## Протокол воспроизведения

[`board_navigation_source_gate.js`](./board_navigation_source_gate.js), **Git blob `eedb861ba590a95baaeb0843371306da2c5e8045`**, 6729 байт. Harness вырезает **реальные функции** `saveNow`, `openBoard`, `createBoard`, `duplicateBoard`, `deleteBoard` из исходного и пропатченного приватного `base29.html` и запускает их в Node VM на синтетических досках/искусственных отказах. В публичный GitHub исходники не загружаются.

**15/15 PASS**, в том числе негативные контроли *исходного* кода:
- оригинал переключает доску после отклонённой записи и после `{removed:true}`;
- оригинал создаёт новую доску после отказа записи;
- оригинал переключает доску, не дожидаясь `saving=true`;
- после патча отказ/удалённая доска/незавершённая запись блокируют переход; успешная запись и чистая доска остаются рабочими;
- дополнительно: предотвращены создание/копирование/удаление при неудачной записи, грязная virtual board и выход за 5-секундный timeout.
