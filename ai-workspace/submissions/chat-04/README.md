## 2. Что сделано

- Дополнительная опциональная настройка вида: `view.group: null | {key:string, dir:'asc'|'desc'}`. При отсутствии `group` объект остаётся прежней формы `{filter,sort}` — регрессии контракта CHAT 03 нет. Выключение группировки отправляет явное `group:null`, чтобы хранилище могло удалить настройку.
- Настройка в панели вида: выбор свойства, отключение, направление группировки по порядку вариантов поля.
- Группы отображаются **строками-заголовками внутри семантической таблицы**, не похожими на самостоятельные блоки доски. У каждой группы есть количество записей и доступная кнопка сворачивания (`aria-expanded`); закрытые группы не участвуют в редактировании и выборе всех.
- Категории значений: **задано** (включая строку `no`, по порядку `options`), **не задано** (отсутствующий или пустой ключ применимого свойства), **неприменимо** (тип сущности не поддерживает свойство). Последние две категории всегда идут в конце независимо от направления.
- Группировка применяется после фильтра и существующей сортировки; порядок записей внутри группы сохраняет результат сортировки и стабильные ничьи. Исходные `entries` не меняются и не перезаписываются.
- При скрытии строк фильтром/сворачиванием их выделение снимается; `onApply` получает только **видимые выбранные** ID. После сохранения записи её новое значение влияет на группу и строки пересчитываются.
- Локальное состояние сворачивания намеренно не записывается в `view` и не хранится на сервере.
- Чистая функция `mountYoutubeTable300.computeGroups(entries, fields, view)`: массив `{id, kind, key?, value?, label, rank?, entries}` без DOM, сети и изменений входов. Существующая чистая `computeView` сохранена.
- Пресеты CHAT 03 автоматически сохраняют/применяют группировку через `view` и `onSaveView`; `onChangePreset` не меняется. Все пользовательские названия вставляются как текст.

## 5. Допущения и открытые вопросы

1. **Одна группировка по одному свойству за раз.** Пользователь попросил группировку по любому свойству, но многоуровневую группировку не описывал. Это сознательно ограниченный контракт, не утверждённое продуктовое решение.
2. Сворачивание групп временное в рамках вкладки: не сохраняется, пока SOL не согласует отдельный контракт.
3. `view.group` не входило в исходный контракт хранилища CHAT 02/03. SOL должен добавить поддержку поля в существующую сериализацию, а не пытаться внедрить новый стор в CHAT.
4. В `computeGroups` сохраняется сортировка внутри каждой группы. Порядок самих групп задаётся `options` выбранного поля, чтобы было предсказуемо при любых нескольких ключах сортировки.
5. Группы с нулём записей скрыты; после редактирования они пересчитываются. Нет отдельной функции ручной перестановки групп.
