# XOD · CHAT 03 — именованные пресеты вида YouTube

**Статус:** готовый пакет для интеграции Sol. База — CHAT 02, ветка `ai-workspace` (`ai-workspace/submissions/chat-02`). `main` не изменялась. Хранилище и интеграционные тесты в XOD — ответственность Sol.

## Содержимое

- `xod-youtube-table300.js` — полная автономная сборка CHAT 02 + интерфейс пресетов CHAT 03.
- `xod-youtube-table300.css` — полный CSS CHAT 02 + стили пресетов (всё внутри `.yt-table300`).
- `xod-youtube-table300-test.html` — автономный HTML-стенд с **26** сценариями: исходные 17 CHAT 02 без изменения + 9 CHAT 03.
- `chat02-to-chat03.patch` — **рекомендуемый для Sol** минимальный unified diff только JS/CSS относительно исходного CHAT 02. Не заменяет внесённые Sol исправления повторов сортировки и глубины групп.

## Контракт

Публичный API не изменён: `mountYoutubeTable300(root, {entries,fields,onApply,view?,onSaveView?,presets?,onChangePreset?})`. Чистый движок `mountYoutubeTable300.computeView(entries,fields,view)` сохранён.

- `presets?: Array<{id:string,name:string,view}>` — исходный отдельный от свойств записей список.
- `onChangePreset?: (command) => Promise<Array<{id,name,view}>>` — **весь** новый список после успешной записи.
- Команды:
  - `{op:'create',name,view}` — сохраняет текущий вид как новый пресет;
  - `{op:'update',id,view}` — заменяет сохранённый вид, сохраняя ID и имя;
  - `{op:'rename',id,name}` — переименовывает, не изменяя вид;
  - `{op:'delete',id}` — удаляет пресет.
- Применение пресета перестраивает таблицу, убирает скрытое выделение и вызывает существующий `onSaveView` с копией выбранного вида; сведения о пресете не смешиваются с `entries[].values`.
- Изменения списка применяются в UI только **после** успешного полного ответа адаптера. При отказе виден текст ошибки и кнопка повтора той же команды с зафиксированными аргументами. Пока операция в полёте, запрещается повторный запуск.
- При уничтожении компонента (`destroy`) результаты ещё не завершённых операций игнорируются; запись в хранилище, уже запущенную адаптером, отменить из компонента невозможно.
- Если `presets` и `onChangePreset` не заданы, панель отсутствует и интерфейс CHAT 02 сохраняется. Если список есть, но адаптера нет, применять пресеты можно, изменения выключены. Если список пуст, показывается явное сообщение.

## Интеграция поверх исправлений SOL

**Не заменять весь JS/CSS в актуальной ветке SOL автоматически.** SOL уже исправил запрет повторных полей сортировки и глубину вложенных фильтров. Перенести только дополнительные блоки пресетов из `chat02-to-chat03.patch`, сохранив эти исправления. Убедиться, что `normalizeYoutubeTable300View`, `renderViewControls`, `refreshFromView`, `saveView` остаются актуальными реализациями SOL.

Рекомендуемая проверка на нетронутом CHAT 02: `git apply --check chat02-to-chat03.patch`, затем `git apply chat02-to-chat03.patch`. В интегрированной сборке, если контекст не совпадает, применять вручную именно добавления, не откатывая исправления SOL. `main` не менять.

Адаптер SOL должен обеспечивать атомарность/последовательность записи пресетов и возврат полного списка. При сетевой неопределённости повтор `create` **не гарантирует отсутствия дубликата без идемпотентности на стороне адаптера**, поскольку контракт команды не включает `operationId`. Это открытый риск для SOL, а не обещание клиента.
