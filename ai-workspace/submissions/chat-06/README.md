# XOD · CHAT 06 — queued onSaveView после закрытия таблицы

**Статус:** доказанная ошибка CHAT 04 и минимальный патч, подготовленный обычным 🟦 CHAT 21.11.2026. **Не интегрировано** в локальную сборку XOD. `main` не изменять, 🟩 SOL остаётся спящим до сообщения 👤 ДИМЫ.

## Текущий шаг
`1. XOD 3.0 → 1.1. YouTube → 1.1.1. Виды таблицы → 1.1.1.3. Текущий шаг · 🟦 CHAT — жизненный цикл сохранения.`

## Доказанный дефект
В исходном `chat-04/xod-youtube-table300.js` функция `saveView()` ставит запросы `onSaveView` в цепочку Promise, но не проверяет `destroyed` **непосредственно перед вызовом адаптера**. Сценарий: первый запрос `group.dir=asc` не завершился → пользователь выставляет `desc` → уничтожение компонента `destroy()` → первый запрос завершается → **второй onSaveView(desc) начинается после закрытия таблицы**. Это может привести к неожиданному изменению настроек уже после размонтирования.

Ещё более короткий воспроизводимый случай: `setGroup(); destroy();` синхронно, до первой микрозадачи. В исходной версии первый `onSaveView` всё равно запускается после закрытия.
