## Воспроизведённые дефекты: `fsmBuild/fsmRebuild/fsmExit`

В исходном Test 13 режим «Умная доска из фильтра» обходит проверку результата сохранения:

1. `fsmEnter` / `fsmBuild`: при отказе `saveNow()` продолжает `vfBuild()` и заменяет открытую доску, хотя `dirty` остался true. При асинхронном создании `vfBuild()` возможны новые изменения после исходного снимка.
2. `fsmExit`: при ошибке виртуального writeback продолжает выход, сбрасывает `S.fsmFrom` и меняет контекст. Если источник отсутствует в Backend, старый код оставляет `S.board=null` и снимает метку режима фильтра.
3. `fsmRebuild`: запрашивает исходную доску **до** сохранения изменённого виртуального вида; при исключении `bfApply()` старый код не восстанавливает временно заменённый `S.board`.

**Отрицательные тесты исходника воспроизвели все перечисленные пути** на настоящих `fsmEnter`, `fsmBuild`, `fsmRebuild`, `fsmExit` с синтетическими отказами Backend. Это доказанный риск логики, но не доказанная потеря пользовательских досок.

- `fsmRebuild`: сначала завершает виртуальную запись, только потом перечитывает исходную доску; временную замену `S.board` оборачивает в `try/finally`.
- `fsmExit`: при отказе writeback или пропаже исходной доски оставляет текущий виртуальный контекст и фильтр нетронутыми; при штатном выходе сохраняет прежнюю функциональность. Очистка фильтров выполняет `await saveNow()` уже на исходной доске. Строгое сохранение не ослаблено, ни один тип ошибки не превращается в ложный PASS.

## Отдельный аудит Split — риск открыт, патч не подготовлен вслепую

В точном исходнике `enterSplit()` вызывает `await saveNow()` без проверки результата и сразу скрывает стандартный редактор. `exitSplit()` сбрасывает `S.split` и уничтожает iframe-панели **до** асинхронной загрузки выбранной доски, после чего может заменить `S.board`. Каждая iframe-панель — отдельный контекст сохранения. Одного `canLeaveCurrentBoard()` для родительского окна **недостаточно** для защиты данных в панелях.

**Отдельный требуемый контракт для Split:** подтверждённый save/prepare от каждой активной iframe, проверка ответа/тайм-аута и только после этого удаление iframe и возврат к одной доске; при отказе любой панели сохранение текущего layout без переключения. До браузерной реализации этого протокола закрытие Split нельзя считать полностью защищённым. Этот блок *проанализирован по исходнику*, но E2E-проверки iframe и исправление **не выполнены**.
