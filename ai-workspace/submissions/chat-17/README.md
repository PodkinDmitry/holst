# CHAT 17 — сохранение изменений умной доски при отказе исходного хранилища (21.11.2026)

**Статус:** воспроизведён дефект на реальной кодовой базе Test 13 `6429ad6`; подготовлен проверенный **неинтегрированный** продуктовый патч с повторной записью. Код XOD `main` и приватный архив не публиковались и не менялись. Выполнено без Work.

## 1. Доказанный дефект

В исходном `v224/base29.html` ветка `saveNow()` для `b.virtual` выставляла `dirty=false` и `setStatus('saved')` **до** окончания `vfWriteBack(b)`. Сам `vfWriteBack` подавлял исключения `Backend.saveBoard`, обновлял `vb.vorig` **до** успешного подтверждения записи и изменял исходную доску из `S.vfCache` **по ссылке**. После ошибки база «уже записанных» изменений менялась, а хранилище могло оставаться старым. Следующий вызов сохранения видел преждевременно подтверждённую подпись и пропускал изменение. Тест на оригинальном источнике реально воспроизвёл **ложный статус saved и пропущенную повторную запись**.

Дополнительно оригинал молча пропускал отсутствующую исходную доску/объект и удалял связь `vmap/vorig` **до подтверждения удаления**. Это риск потери изменений, не доказательство потери на пользовательских реальных досках.

## 2. Минимальный безопасный исправляющий контракт

- **Виртуальная ветка `saveNow()`:** ждать `vfWriteBack` и использовать тот же цикл `saving/dirty/saveAgain`. `saved` только при успехе; ошибка сохраняет `dirty=true`, показывает `error` и общее предупреждение без содержимого доски.
- **`vfWriteBack()`:** готовить изменения в отдельной копии доски, **сохраняя базовую ревизию в `localBoardBases300` WeakMap**. Иначе реальный IndexedDB-движок мог бы счесть существующую доску конфликтной — это обязательная часть патча, подтверждённая исходником `v224/m_data300.js`.
- **Подтверждение записи:** только после `await Backend.saveBoard(b)` и если `result?.removed` не равен true обновлять `vb.vorig`, `vfCache` и отображаемый индекс. Успешная часть группы из нескольких досок считается подтверждённой; ошибка в другой доске оставляет `dirty=true` и её подпись для повторной записи без дублирования остальных.
- **Удаление:** подтверждённые удаления исходных объектов удаляют `vmap/vorig` только после успешной записи. Выбор «Только здесь» сохраняет исходные объекты и снимает ссылки виртуального представления.
- **Переходы:** `vfShow` и кнопка закрытия умной доски не переключают контекст, если сохранение ещё выполняется или завершилось ошибкой.

Обычный путь `saveNow()` для не-виртуальной доски **не менялся**. Данные пользователя, формат сохранения и приватный код не публиковались.
